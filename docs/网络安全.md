# 网络安全说明（部署必读）

这台服务暴露在公网上，处理的是老人的声音和对话。下面按「谁能连上来」把网络面说清楚。挑毛病的人最常问这些。

## 1. 对外到底开了什么

```text
互联网
  │  只应放行 80 / 443
  ▼
nginx（HTTPS / WSS）
  ├─ /xiaozhi/ota*     → 127.0.0.1:3096   设备 OTA（设备口令 + MAC 白名单）
  ├─ /xiaozhi/ws       → 127.0.0.1:3097   设备语音 WebSocket（口令）
  ├─ /ws/intercom      → 127.0.0.1:3098   管理台对讲（登录 Cookie）
  ├─ /ws/call          → 127.0.0.1:3095   浏览器测试通话（登录 Cookie）
  ├─ /v1/              → 127.0.0.1:3093   可选电话线路（Bearer）
  └─ /                 → 127.0.0.1:3093   管理台网页与 API（登录 Cookie）
```

**后端端口 3093–3098 只绑定 `127.0.0.1`。** 云厂商安全组 / 本机防火墙不要放行它们。若有人能直接打到这些端口，就等于绕过了 nginx 的 TLS 和部分防护。

## 2. 三道门分别挡谁

| 门 | 挡什么 | 怎么开 |
|---|---|---|
| HTTPS 证书 | 链路窃听、中间人 | `install.sh` + certbot |
| 管理台登录 | 浏览器访客 | `ADMIN_PASSWORD_HASH`；家人用 `admin_password.py --role family` |
| 设备口令 + MAC 白名单 | 陌生设备连上来刷接口费、灌对话 | `XIAOZHI_DEVICE_TOKEN`、`XIAOZHI_ALLOWED_DEVICE_IDS`、`XIAOZHI_REQUIRE_DEVICE_TOKEN=1` |

只「域名比较偏」不够：扫描器、误配 DNS、历史截图里的域名都会撞上你的 443。

## 3. 设备侧（没有网页登录）

- 设备启动先访问 `https://你的域名/xiaozhi/ota/`，服务器在回复里下发 WebSocket 地址和口令。
- **MAC 白名单可以伪造**，真正挡住陌生人的是 `XIAOZHI_REQUIRE_DEVICE_TOKEN=1`：口令只在 OTA 时发给白名单里的设备。
- 没有任何照片上传入口：桥接服务不接收图片，固件补丁不初始化摄像头。
- 第一台设备刚连上、还没写白名单之前，任何知道域名的人都能连——所以设备一出现在日志里，立刻填 MAC 并打开 `REQUIRE_DEVICE_TOKEN`。

## 4. 管理台侧（有 Cookie）

- Cookie：`HttpOnly` + `Secure` + `SameSite=Lax`，默认约 180 天。手机丢了先改密码并退出。
- 写操作会校验浏览器 `Origin` 与 `Host` 同站，降低跨站 POST 风险。
- 对讲 / 通话 WebSocket 走 nginx `auth_request`，未登录进不来。
- 家人账号看不到「维护」、改不了密钥/人设/重启/OTA；能看记录、对讲、出题。

## 5. nginx 模板里故意做的几件事

- 每个 `location` 都把 `Tailscale-User-Login` 清空：防止公网访客伪造「内网已登录」。
- `server_tokens off`、`X-Frame-Options DENY`、`X-Content-Type-Options nosniff`。
- WebSocket 长连接超时拉长；普通上传限制约 32MB（固件）。

不要为了「省事」把后端端口映射到公网，也不要删掉清 `Tailscale-User-Login` 的那几行。

## 6. 内网穿透 / 家里 NAS

用 frp、花生壳、Cloudflare Tunnel 等把家里电脑暴露出去时：

- 仍然要 HTTPS、强密码、设备口令；
- 假设穿透链路的对端不可信；
- 老人那边一旦穿透断了，就是「拍了没反应」——稳定性要自己保证。

## 7. 备份与日志也是攻击面

- `data/` 含录音、对话、记忆；备份加密存放，不要丢进公开网盘。
- `journalctl`、nginx access log 可能留下原话片段；贴日志到 issue 前先脱敏。
- `.env` 权限 `600`，永远不要进 git。

更多条目见 [SECURITY.md](../SECURITY.md)。

## 8. 浏览器这一侧（CSP 与权限）

- 所有页面（管理台、登录、故事书、致敬页）的脚本和样式都是外置文件，页面里**没有内联脚本、内联样式、`onclick` 一类内联事件**。所以 CSP 可以收得很紧：`script-src 'self'`、`style-src 'self'`，都不带 `'unsafe-inline'`。动态内容一律先转义再进页面。
- `Permissions-Policy`：麦克风只给同源（对讲要用），**摄像头、定位、支付、USB、录屏一律禁用**。
- `frame-ancestors 'none'` + `X-Frame-Options: DENY` 防点击劫持；`Referrer-Policy: same-origin`。
- 这些规则在 `web_auth.py` 和 nginx 模板里各写了一份；`tests/test_safe_next.py` 检查响应头，`tests/test_web_static.py` 检查页面里没有混进内联代码。
- 管理台静态文件（`/app.css`、`/app.js`）也要登录才能拿到。未登录能访问的只有登录页资源、`/thanks`（致敬页）及其静态文件、favicon。
- 家人账号拿到的设备状态是裁剪过的（`glance.py`）：只有在线、电量、最后在线时间和与设备直接相关的提醒；看不到设备号、开机记录、待升级固件，服务类告警也只显示「已通知管理员」，不显示原文。
