# 跨平台本地运行与局域网联调（Windows / macOS）

> 公网长期部署仍推荐 Ubuntu 22.04+ / Debian 12+（见 [docs/部署.md](部署.md)）。
> 本页说明如何通过 **Docker**、**Windows** 或 **macOS（含 Apple Silicon）** 本地预览管理台、运行服务，以及不买云服务器直接用局域网真机联调。

## 零、Docker 一键体验与自托管（不侵入宿主机）

如果机器装了 Docker，不想改动宿主机环境，可以直接用仓库根目录的 `Dockerfile` 与 `docker-compose.yml`（不影响原有的 `deploy/install.sh` + systemd 路线）：

```bash
# 1) 零配置演示模式（自动生成虚构数据，浏览器打开 http://127.0.0.1:3093）
docker compose --profile demo up --build
# 国内拉取 pip 慢可先传清华源构建：
# docker compose --profile demo build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple demo

# 切换演示场景（ok / talking / charging / low / offline / alert）
DEMO_SCENE=low docker compose --profile demo up --build

# 2) 自托管完整模式（需先在根目录备好 .env、family.json、persona.md，含 ADMIN_PASSWORD_HASH 与 XIAOZHI_CTL_TOKEN；
#    Linux 宿主机请先创建并授权 UID 1000 写权限：mkdir -p data public && chown 1000:1000 data public）
docker compose --profile serve up -d --build
```

> 默认只将 `3093`、`3095–3098` 绑定到宿主机 `127.0.0.1` 并设 `ALLOW_LOCAL=0`，`.env` 以卷挂载并由入口脚本逐行安全加载（不会误展开哈希里的 `$`），公网暴露请搭配宿主机 Nginx / Caddy / Traefik 配置 HTTPS 与 `/_auth` 鉴权（见 [deploy/nginx.conf.template](../deploy/nginx.conf.template)）。改完 `.env` 后执行 `docker compose --profile serve restart wozaine` 生效；定时任务可用宿主机 cron 经入口脚本调用：`docker compose --profile serve exec -T wozaine /app/deploy/docker-entrypoint.sh python3 daily_report.py` 与 `device_monitor.py`。

## 一、Windows 本地运行

### 前置依赖

- Python 3.10+（推荐 3.12）
- `ffmpeg`（加入系统 `PATH`，音频转码用；可通过 `winget install Gyan.FFmpeg` 安装）
- `opus.dll`：安装 `requirements.txt` 时 Windows 会自动安装 `pyogg`（BSD-3-Clause），`platform_compat.py` 启动时会自动定位其中的 `opus.dll`，通常无需手动复制 DLL

### 一键启动脚本

仓库提供 PowerShell 启动脚本 [deploy/start_windows.ps1](../deploy/start_windows.ps1)：

```powershell
# 1) 无硬件演示模式（自动生成虚构数据，启动演示桥接 + 管理台）
.\deploy\start_windows.ps1 -Demo

# 切换演示场景（ok / talking / charging / low / offline / alert）
.\deploy\start_windows.ps1 -Demo -Scene low

# 2) 本地完整服务模式（需先配好 .env、family.json、persona.md）
.\deploy\start_windows.ps1
```

启动后浏览器打开 `http://127.0.0.1:3093` 即可访问管理台。按 `Ctrl+C` 退出时脚本会自动清理子进程并还原临时环境变量。

> [!NOTE]
> - Windows 与 macOS 本机运行不使用 `systemd`，管理台「维护」页会通过探测本地端口显示服务状态，不支持页内一键重启——修改 `.env` 后请退出脚本并重新启动（若自行在终端里 `export` 过变量，请重开终端或重新加载 `.env`）。
> - `-Demo` 模式只将业务数据目录切换到 `demo-data/`，仓库根目录的 `.env` 和 `persona.md` 仍为共享路径；如果仓库里已有正式配置，请勿在演示模式里保存修改密钥或人设。
> - 直接访问 `http://127.0.0.1:3093`（未经过 nginx 或 `tailscale serve` 反代）时，前端的网页「通话」与「对讲」默认连开发端口 `8458` / `8459`，如需使用这两项功能请按 [docs/部署.md](部署.md) 配置反代。

## 二、macOS 本地运行（含 Apple Silicon）

### 前置依赖

```bash
brew install opus ffmpeg
# 推荐使用 Python 3.12（避免系统自带的 3.9 或过新预览版）
python3.12 -m venv venv          # 或：uv venv --python 3.12 venv
venv/bin/pip install -r requirements.txt
```

- 启动时 `platform_compat.ensure_opus_dll()` 会自动发现 Homebrew（`/opt/homebrew/lib`、`/usr/local/lib`）或 MacPorts 的 `libopus.dylib`，无需手动设置 `DYLD_FALLBACK_LIBRARY_PATH`。
- `bridge_media.ensure_opuslib_ctl_argtypes()` 已为 `opuslib` 的变参 C 接口补齐固定参数签名，避免在 Apple Silicon（arm64）上设置码率或复杂度时读到栈垃圾值导致参数失效、报错或崩溃。

### 演示模式 / 完整启动

```bash
# 演示模式（不花钱、不需要硬件；注意仓库已有正式 .env / persona.md 时请勿在演示界面里点击保存）
venv/bin/python3 tools/demo_data.py demo-data
COMPANION_DATA_DIR=demo-data venv/bin/python3 tools/demo_bridge.py --scene ok &
COMPANION_DATA_DIR=demo-data venv/bin/python3 server.py
```

完整运行（已配好 `.env`、`family.json`、`persona.md`）。**请勿直接 `source .env`**：`.env` 里的 `ADMIN_PASSWORD_HASH` 含 `$` 符号、`ALERT_COMMAND` 可能含空格，shell 直接执行会误展开；请用下面的逐行导入方式启动：

```bash
# 终端 1：设备桥接（OTA :3096 / WS :3097）
(
  while IFS= read -r line; do
    case "$line" in ''|'#'*) continue ;; *=*) export "${line%%=*}=${line#*=}" ;; esac
  done < .env
  exec venv/bin/python3 -u xiaozhi_bridge.py
)

# 终端 2：管理台（http://127.0.0.1:3093）
(
  while IFS= read -r line; do
    case "$line" in ''|'#'*) continue ;; *=*) export "${line%%=*}=${line#*=}" ;; esac
  done < .env
  exec venv/bin/python3 -u server.py
)
```

## 三、不买云服务器，局域网真机联调

想先在家里电脑上把实体板子跑通，再决定是否上云，可按下面几步配置：

1. 查看电脑和设备所在同一 Wi-Fi 下的局域网 IP（如 `192.168.1.100`）：
   - macOS：`ipconfig getifaddr en0`
   - Windows：`ipconfig`（看无线局域网适配器的 IPv4 地址）
2. 在 `.env` 中将桥接服务的公开地址改为本机局域网地址：
   ```ini
   XIAOZHI_PUBLIC_OTA_URL=http://192.168.1.100:3096/xiaozhi/ota/
   XIAOZHI_PUBLIC_WS_URL=ws://192.168.1.100:3097/xiaozhi/ws
   ```
3. 启动 `xiaozhi_bridge.py` 时将监听地址设为 `0.0.0.0`（放行局域网设备接入），并确保系统防火墙允许 `3096` / `3097` 入站：
   ```bash
   # macOS / Linux
   (
     while IFS= read -r line; do
       case "$line" in ''|'#'*) continue ;; *=*) export "${line%%=*}=${line#*=}" ;; esac
     done < .env
     XIAOZHI_OTA_HOST=0.0.0.0 XIAOZHI_WS_HOST=0.0.0.0 exec venv/bin/python3 -u xiaozhi_bridge.py
   )
   ```
   ```powershell
   # Windows PowerShell
   $env:XIAOZHI_OTA_HOST="0.0.0.0"; $env:XIAOZHI_WS_HOST="0.0.0.0"
   .\deploy\start_windows.ps1
   ```
4. 设备端（编译配置 `CONFIG_OTA_URL` 或配网页高级选项里的自定义 OTA 地址）填写 `http://192.168.1.100:3096/xiaozhi/ota/`。

> [!WARNING]
> - 明文 `http://` / `ws://` 与 `0.0.0.0` 监听**仅限受信家庭局域网临时调试**。公网部署务必保持服务监听 `127.0.0.1`，并经 nginx HTTPS 反代和登录鉴权（见 [docs/网络安全.md](网络安全.md)）。
> - 局域网直连模式下 OTA HTTP（`:3096`）与 WebSocket（`:3097`）分属不同端口，而固件下载地址由 `XIAOZHI_PUBLIC_WS_URL` 推导，因此局域网直连仅用于对话联调，不支持在线推送 OTA 固件包（升级请直接 USB 烧录，或在公网 nginx 同域反代下使用）。

## 四、本机验证

无论在 Linux、macOS 还是 Windows，都可以先跑离线单测与桥接冒烟场景：

```bash
# 纯离线单测（不访问网络、不调用任何云服务；Windows 将 venv/bin/python3 换成 venv\Scripts\python.exe）
venv/bin/python3 tests/test_platform_compat.py
venv/bin/python3 tests/test_bridge_media.py
venv/bin/python3 tests/test_bridge_session.py
venv/bin/python3 tests/test_deepseek_client.py
venv/bin/python3 tests/test_asr_client.py
venv/bin/python3 tests/test_typo_book.py

# 桥接进程冒烟（验证 OTA、鉴权、WebSocket 握手；不调用 ASR/LLM 对话接口，
# 但 smoke 会请求免费天气接口 Open-Meteo，若本地尚无 data/fallback 缓存且配置了 TTS 密钥会合成一次兜底语音）
venv/bin/python3 tests/run_scenarios.py smoke auth ota
```
